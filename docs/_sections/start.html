Quickstart

Python 3.10+ and either claude or codex on your PATH. No third-party dependencies. 

uv tool install rmc-memory
rmc install --scope user
rmc doctor

That is the whole install. rmc install wires the hooks and RMC runs in every repo you open — you do not drive it, you work normally. Drop --scope user to limit it to one project.

The distribution is rmc-memory because rmc was taken on PyPI. The command it installs, and the package you import, are both rmc. No uv? pipx install rmc-memory. Just trying it? uvx rmc-memory doctor.

What you should see

Nothing, at first — the store is empty and RMC has nothing to say. Once it has learned something, a line appears above your prompt:

⋯ RMC · 2 lessons · 512 tok — Retry policy, Cache TTLs
⋯ RMC · 1 lesson · 118 tok — Retry policy  · 1 refreshed, 2 already in context

It names what was loaded, because a count only proves RMC fired — the titles are what let you notice it fired on the wrong lessons. The three states differ: a lesson injected in full, a one-line refresher for one going stale, and one skipped because it is still in your context. Only the first is a lesson arriving.

Expect the first capture within a few sessions of real work. RMC learns from corrections, so a session where nothing went wrong teaches it nothing.

Where your data lives

Plain files: .rmc/ in the project, ~/.rmc/ for lessons that apply everywhere. Nodes and episodes are worth committing; sessions, telemetry and caches are machine-local. Everything passes through redact.py before it touches disk — API keys, tokens, private keys, card numbers — biased toward over-redaction, since a mangled lesson is recoverable and a leaked key is not.

RMC makes no network calls. Model calls go through whichever CLI you already have, under your existing credentials.
