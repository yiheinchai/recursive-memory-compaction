When something looks wrong

Start with rmc doctor. It reports backends, store, hook wiring, and whether the rmc command is on your PATH.

SymptomLikely causeCheck / fix
rmc: command not found The CLI is not on PATH. Hooks are unaffected — they invoke the package by absolute path, so RMC is still running. rmc install links it; or symlink bin/rmc into ~/.local/bin yourself
Nothing is ever recalled An empty store, or every match is already fresh in your context rmc tree for what exists; rmc recall --prompt "…" for what a given prompt would pull
Nothing is ever learned No backend, no substantial turns, or the reflection backoff has grown rmc status — look at nudges and the miss rate; rmc events --kind nudge for when one last fired
Hooks never fire Installed at project scope into a repo you do not work in — including RMC's own clone rmc doctor shows where they are wired; rmc install --scope user fixes it
The wrong lessons keep appearing Recall over-serving, the weakest part of the system today rmc trace --prompt "…" shows the model's verdict and reason for every candidate
A lesson is wrong or out of date It was captured from a situation that has since changed rmc conflicts, then rmc resolve <id> --drop
A bug in RMC itself — rmc report --about "…" writes a redacted report and prints the gh command to file it. It sends nothing.
