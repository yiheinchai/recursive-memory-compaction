Coming from Claude skills

If you already keep engineering knowledge as a directory of SKILL.md files — especially one grown by an introspection skill that writes new skills as it learns — you have built a manual version of this. Migration converts it. 

rmc migrate                    # plan: scans ./.claude/skills and ~/.claude/skills
rmc migrate --apply            # write the lessons
rmc migrate --path ~/other/skills --limit 5

It is not a file conversion. A skill is a document holding several separate claims; a lesson is one claim plus the situation that summons it. So each skill is read and split, and three rules govern the result:

RuleWhy
Capture machinery is not imported Skills whose subject is writing, indexing or syncing skills — introspect, create-skill, sync-skills — are reported as superseded. RMC does that itself; importing them would fill the store with instructions for maintaining the system you are leaving.
Nothing is deleted Migration only adds. Retiring a skill is your call, made after you have seen rmc recall return the same knowledge.
Everything goes through normal placement Bulk import is exactly where reconciliation matters: a library grown over months contains near-duplicates and outright contradictions, and a fast path would import both sides of a disagreement in silence.

The description: field of a skill is already a gist — it states when the skill applies — so it carries across directly, which is what lets recall fire on knowledge you previously had to remember to invoke.

Afterwards, check a few things you know a skill covered: rmc recall -p "deploy the schema registry". When RMC returns the same knowledge, the superseded skills are the safest to delete first.
